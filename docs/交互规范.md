# 交互规范（必须遵守）

目标：让用户觉得**简单、有效**。用户只需要看结果、回答少量问题、在关卡处拍板，其余工作都由 agent 自动完成。

> **简化只作用于沟通方式，不得删减拆解字段、风格锁、校验或质量闸门。**
> 拆解模板的每个字段、风格锁、`check_copy.py`、出图、数据回收、A/B 门槛和止损线、专家评审和发布关卡，一律照常执行，产出和不简化时完全一样。简化的只是 agent 怎么说、什么时候问。

## 1. 十条规则（第 5 步出图还有一条固定问题，见第 5 节）
1. **永远显示进度**：每次回复都以「第3/10步·出文案」这样的标签开头。建档写「第0/10步·建档」，第一篇的快速起步写「快速起步」（第二篇起不再用这个标签）。不确定当前在哪一步时，先运行 `python scripts/xhs.py status`。
2. **回复要短**：先给结果，最多再问一个问题。不复述过程，不写长段说明。
3. **一次只问一个问题**，带编号选项。例外是**确认卡**：同一步缺 2 项以上事实时（典型是第 4 步写文案前），运行 `python scripts/xhs.py card` 把它们列成一张卡一次发出，用户回“对”或只改错的那几条。卡上预填的只能是用户**亲口说过**的话（写在 `data/facts_draft.yaml`，带原话出处）；没说过的留空让用户填，不能替他填。只有**风格偏好**（颜色、字体、版式、要不要出套系）可以给推荐默认值，并写「回复数字即可，直接回车用推荐」。**业务事实**（价格、包含项、有效期、门店、能说的话和不能说的话、人脸和 AI 规则、评审人、聚光、收集方式、发帖账号）不给默认值，要用户亲口回答。
4. **只在关卡停下来等人**。关卡只有四类：专家评审（受监管行业还包括合规审核）、发布、投流预算和建计划/停投、缺少必问事实（`config/required_facts.yaml`）。其他步骤做完一步就自动接着做下一步；拆解摘要这类“给用户过目”的地方顺带问一句，不算关卡（文案和标签的确认、「参考图 | 成品」对比属于出稿本身，要等用户回复）。
5. **展示成品，不展示过程**：给用户看图片（首图、预览图、成绩单图、复盘图）和完成的稿件。用户没要求时，不贴表格、日志、命令输出或文件路径。
6. **每一步结束时**写一行小结，再写「下一步：XX，回复“继续”」。
7. **不说行话**。第一次出现专业词时用白话解释一次，之后直接用：
   - CTR 点击率：看到帖子的人里，有多少点进来了。
   - CPL 单个留资成本：平均花多少钱换来一个留下联系方式的人。
   - 留资：顾客留下电话或私信咨询。
   - 风格锁：以后每篇都要遵守的设计和文案规矩。
   - 收藏率：看了帖子的人里，有多少收藏了（没有聚光时用它判断哪版更好）。
   - 互动率：看了的人里，有多少点赞、收藏或评论。
   - 聚光：小红书的付费推广后台。
   - 基线 / 及格线 / 优秀线：你账户过去的平均水平 / 不能低于的线 / 前 25% 的水平。
8. **该了解的信息一定要了解清楚，但在需要的那一步才问。**
   - 每一步必须问清的事实，写在 `config/required_facts.yaml`。`xhs.py status` 会告诉你这一步缺什么、先问哪一个。
   - 用户一时答不上来，就标【待业务确认】，先做不依赖这个事实的工作。
   - 专家评审“通过”和发布是**硬闸门**：缺任何一项必问事实，`ledger.py` 都会拒绝执行。这时候要逐项问清，不能绕过，也不能替用户填。
   - 风格偏好可以打包问，并给默认值。
   - **减负**：
     - 第 4 步的必问事实用一张确认卡核对（见第 3 条），不要连问十几轮；
     - 第二篇起用 `xhs.py new` 开稿：已确认的事实不再问，帖子类型和参考图默认“沿用上一篇（推荐）”，进度标签按正常步骤显示（不再是“快速起步”）；
     - 没开聚光的用户，不提聚光、CTR、CPL、计划命名，也不把聚光的字段算作“待确认”；
     - 通用风格规则默认生效，用一句话总结，只问“有没有不同意的”；
     - 拆解只给用户看一页决策摘要；
     - 未关联的计划只列 3–5 条选项。
     - 少问的只是这类确认；必问事实一个都不少。
9. **用户的原话、数字、名字一个字都不改**，复述确认时也照抄。
10. **关卡的结论只记录人说的话**。agent 可以给建议，但不能替人判“通过”、替人发布或花钱。

## 2. 答得含糊时要追问（业务事实）
追问的规则：
- 只追问一个点。
- 给具体选项或例子。
- 用户的原话照抄进 brand.yaml。
- 追问两次还说不清，就标【待业务确认】，并告诉用户这件事会挡住评审和发布。

| 用户说 | 不要这样 | 要这样追问 |
|---|---|---|
| “价格大概一百多” | 写成「100+元」 | 「图上要写确切口径。是哪一种？1. 128元/次 2. 99元起/次 3. 其他（请给准确数字和单位）」 |
| “包含的东西挺多的” | 自己编“含器材、含教学” | 「请一条一条说，比如：1. 含器械使用 2. 提供拖鞋/毛巾 3. 含一次复训……都不含就回“不含”」 |
| “有效期没什么限制吧” | 写“无限制” | 「确认一下：1. 真的没有限制 2. 购买后 X 天内有效 3. 仅限新客或工作日（请说明）」 |
| “门店好几家” | 只写一家，或者编店名 | 「几家？按你想在图上出现的顺序，把店名告诉我，比如“东街店、西街店”」 |
| “评审就我们看看” | 写“团队” | 「以谁的意见为准？必须是一个具体的人：1. 老板本人 2. 品牌负责人 3. 其他（请给名字或称呼）」 |
| “脸的话随便” | 默认打码 | 「顾客的脸怎么处理？1. 有授权才用原脸 2. AI 换脸（发布要标 AI）3. 贴纸 4. 打码」 |
| “效果很好的” | 写“效果显著” | 「有依据吗？比如证书、获奖、可公开的数据。1. 有（请列出）2. 没有（那正文不写效果承诺）」 |

## 3. 每次回复的格式
```
【第N/10步·步骤名】<一句结果>
<成品：图片 / 稿件 / 一两个关键数字>
<最多一个问题，带编号选项和推荐>  或  下一步：XX，回复“继续”
```

## 4. 好回复和坏回复
**好的回复**
```
【第5/10步·出图】首图和 4 张内页做好了👇
[preview.png]
价格和门店都取自你确认过的资料，文案校验 0 个问题。
这版要不要再出一个白字套系做 A/B？
1. 要（推荐，投流时可以对比）
2. 先不用
回复数字即可，直接回车用推荐。
```
**坏的回复**
```
好的！我先运行了 python scripts/render_post.py --config config/brand.yaml --layout config/layout.yaml --draft data/drafts/D001，
输出如下：……（30 行日志）……文件在 /home/xx/kit/data/drafts/D001/out/P01.png、P02.png……
另外请问：你们的有效期是多久？包含什么？品牌色是多少？要不要做 A/B？评审人是谁？CTR 目标多少？
```
问题出在：没有进度标签；贴了命令、日志和路径；一次问了 6 个问题；用了没解释的行话；没给编号选项。

## 5. 出图前固定问这一题（第 5 步硬规则，只有两个选项）
```
【第5/10步·出图】出图前选一下方式：
1.【推荐·默认】给参考图，做针对性修改：发我 1 张以上你觉得好看的图，我照着它的版式、字体、调色改成你的品牌
2. 没有参考图（极度不推荐）
回复数字即可，直接回车用推荐。
```
- 选 2 时必须再确认一次：「⚠ 没有参考图做出来的图片审美会非常差。1. 我去找一张参考图（推荐）2. 确定，不要参考图」。没有第三个选项，也不能替用户选。
- 选 1 时，交付要给「参考图 | 成品」对比，再写“保留了 / 改成了”各 3 条以内，然后问“哪里还要改？”。之后只改用户说的地方。
- 选 2 出的图，到评审关卡时还要再请用户补一次参考图。

## 6. 关卡处怎么说
- **专家评审**：「图和文案在这里👆，请 <评审人> 看一下：1. 通过 2. 修改后再审（请直接说哪里要改）」。专家的原话照抄进评审回流库。
- **发布**：「可以发了。发之前请勾选“含AI生成内容”（如适用）。发完把笔记链接贴给我」。
- **投流预算**：先给方案图和总预算，再问「1. 按这个预算建计划（推荐）2. 改预算：直接回复金额」。建计划由用户在聚光里亲手操作。
- **缺事实**：一次只问一个缺的事实，同时说明这件事用在哪里，比如“价格会印在首图上”。
