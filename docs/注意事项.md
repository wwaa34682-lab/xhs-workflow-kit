# 注意事项（合规与风险）

## 1. 事实与承诺
- 价格、时长、包含项、门店、资质、有效期、效果，只能用 `brand.yaml` 里确认过的内容。不知道的写【待业务确认】。
- 不做效果保证和绝对化承诺。`check_copy.py` 会拦截这类用语。
- 虚构或改编的第一人称故事，要标注「情景演绎」。

## 2. 对标素材与版权
- 不管是手动提供的还是小号采集的，对标帖的图片和文案**只用于设计研究**：不二次使用、不商用、不换脸、不搬运，也不把对标图片当本品牌的素材。
- 图上的他牌价格、权益、资质只记录“展示了什么”，不核验，也不背书。
- 评论证据只保存短句，不保存用户名、头像、评论ID。
- 遵守小红书的用户协议、社区规范和著作权规定。研究资料只放在本地 `data/`，不要公开分享。

## 3. 帖子收集的两种模式
| | A 手动提供 | B 专用小号自动搜集 |
|---|---|---|
| 谁能用 | 任何 agent | 只有能控制浏览器的 agent（不能控制浏览器的一律用 A） |
| 用什么账号 | 不需要 | **专门用来研究的小号**。绝不能用品牌主运营账号或员工个人主号 |
| 登录 | — | 用户本人登录。扫码、短信、验证码都由用户本人完成 |
| 方式 | 用户发截图、图片、正文 | 只用普通网页，像正常人一样搜索、打开、保存 |
| 节奏 | — | 每次 ≤30 篇（`max_posts_per_session`），每篇之间随机停 8–20 秒；遇到验证或“操作频繁”立即停下 |
| 风险 | 无平台风险 | 小号可能被限流、要求验证或封禁。**用户须事先接受**（`user_accepts_platform_risk: true`） |

模式 B 明确禁止：
- 调用私有接口或抓包；
- 读取、导出 cookie 或 token；
- 保存账号密码；
- 破解或绕过验证码；
- 反检测、伪装指纹、多开；
- 高频批量抓取；
- 采集和研究无关的内容。

## 3a. 受监管行业（医疗、医美、教育、金融）
- 在 `brand.yaml` 写 `compliance.profile`。`check_copy.py` 会自动加载 `config/compliance/` 的起步包，检查违禁词、违禁句式、必带免责语和资质出处。起步包只是起点，**不是法律意见**。
- 不写第一人称体验故事，不用患者、学员、客户的口吻作证明。“情景演绎”标注在这里不算免责。
- 资质（执业许可、广告审查证明、医生资质）要用原文，发布前由合规审核人（`compliance.reviewer`）过一遍，并记下来：`ledger.py review --type 合规 --verdict 通过 --reviewer <审核人>`。没有这条记录，`ledger.py queue --status 已发布 / 投流中` 会拒绝（硬闸门）。
- 教育行业：效果承诺最容易踩雷（“3个月开口”“效果看得见”“提分快”“一节课学会30个单词”）。起步包会拦这类句式；“名额有限”“立即报名”这类紧迫感说法、“不推销”“一对一”“外教”这类服务说法，没在 `brand.yaml` 里确认过也会被拦。
- 面向未成年人（`compliance.minor_audience` 以“是”开头）：建档时就问；投流前合规审核人还要单独确认一次投流（`--type 合规·投流`）。
- 机构口吻写“我们…”是允许的；不允许的是顾客、学员、家长、患者口吻（“我家孩子…”“我去试了…”）。
- 评论和私信里的健康信息、病情、财务状况属于敏感个人信息：不摘录、不入库。咨询证据只写“问价 / 问地点 / 问预约”这类意向。
- 模式 B 搜索时，不要搜索或保存患者案例、术前术后对比图。

## 4. 人脸与 AI 标注
- 照片里的人脸按 `face_policy` 处理。用了 AI 换脸或 AI 生成画面，发布时必须勾选「含AI生成内容」。
- 换脸只能换成合成的非真实人物，不能换成真实存在的人或公众人物。
- 常见换脸模型（例如 insightface inswapper）只许非商业使用。商用账号使用前，请自行确认模型许可。

## 5. 人工关卡与花钱
- 下面这些都必须由人决定，agent 不能代劳：
  - 专家评审的结论；
  - 发帖；
  - 在聚光建计划、调预算、停投；
  - 让风格锁的提议生效。
- 模拟数据（`--sim`）只用来走通流程，不能拿来改规则，**也不能据此停投、放量或改预算**。模拟复盘只会写“演练里暂列第一 / 演练里偏弱”。
- 模拟复盘里如果各版都是 0 留资，先查留资列（`juguang.lead_field`）是不是和导出表对上了，而不是下结论。

## 5a. 没有聚光时的 A/B（同号轮流发）
- **不要把同一篇原样发两次。** 图文几乎一样的笔记可能被判成重复内容，被限流，严重时影响账号。
- 替代做法：两篇测同一个变量（比如首图版式、首图照片），标题、正文开头和内页换成同主题下的不同角度；同一星期几、同一时段，间隔 3–7 天。
- 这样比出来的是“方向”，结论按“暂定”看。需要严格对照时用聚光：同一篇笔记挂不同创意（首图）。

## 6. 隐私
- `data/`、`raw/`、`config/brand.yaml` 默认被 `.gitignore` 排除，不要提交到公开仓库。
- 不要把账号密码、cookie、token 发给 agent，也不要写进任何文件。
