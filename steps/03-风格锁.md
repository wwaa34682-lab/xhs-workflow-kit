# 第 03 步 · 风格锁（规则库）

**目标**：把“怎么做才对”写成一条条能执行的规则。第 4、5 步出稿必须遵守；第 6、10 步的反馈会不断修改这些规则。

**输入**：
- `data/tables/风格锁.csv`：`--init` 时已经拷入 15 条通用起步规则 SL-G01…G15，并且**自动生效**。受监管行业的合规起步包会自动停用不适用的规则，比如医疗停用 SL-G10 情景演绎和 G15 真人出镜。
- 第 1、2 步的结论。

**和用户怎么说（减负：不要逐条讲 15 条）**
用一句话总结通用规则：「像小红书笔记、不像广告；事实只用你确认过的；价格不当钩子；主体上的字要清楚；有 AI 就标注」。
然后只问一个问题：“这几条里有没有你不同意的？1. 都同意（推荐）2. 有（直接说哪条）”。
具体某条规则，等到第 6 步评审遇到了再调整。

**给 agent 的提示词**
```
1. 基于对标和自有的差距，起草 3–6 条本品牌规则（SL-B01 起），覆盖品牌色、字体、首图主体、信息顺序和禁区。
   每条写清「必须做」「禁止做」「依据来源」（样本ID）。状态先写“提议·待专家确认”：
   python scripts/ledger.py --data data rule --id SL-B01 --dim 配色 --rule "..." --must "..." --ban "..." --status 提议·待专家确认
2. 把这几条提议打包给专家看一次（一屏讲完，每条一句白话），专家回复“同意 / 不同意第 X 条”：
   同意的：python scripts/ledger.py --data data approve --id SL-B01 --note "<专家原话>"
   不同意：加 --reject。
3. 用户否决某条通用规则时：python scripts/ledger.py --data data approve --id <ID> --reject --note "<原话>"。
```

**产出**：更新后的 `风格锁.csv`。

**人工关卡**：本品牌规则（SL-B*）和数据得出的规则（SL-P*、SL-AD*、SL-ORG*），只有专家确认后才能生效。通用起步规则默认生效，用户可以否决。模拟规则（SL-SIM-*）**只能否决**，脚本会拒绝让它生效。

**完成标准**：风格锁覆盖品牌色、字体、首图、信息顺序、事实与承诺五个维度，并且都是生效规则。
