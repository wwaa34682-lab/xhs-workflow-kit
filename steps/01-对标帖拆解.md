# 第 01 步 · 对标帖收集 → 入库 → 拆解

**目标**：把 5–20 篇同行业（或相邻行业）的爆款帖拆成结构化数据，弄清它为什么能被点开、被咨询，以及哪些能迁移到本品牌、哪些不能照搬。
**拆解一律按 `templates/拆解模板.md` 的 A 部分**（用户自己的对标库结构：筛选门槛 / 样本概览 / 逐帖摘要 / 逐图详解 / 咨询证据 / 图示决策摘要）。填写示例见 `templates/拆解模板_填写示例.md`。

收集方式在 onboarding 第 16 题里选好，写在 `brand.yaml` 的 `collection.mode`。两种方式最后都放进**同一个收件箱格式**，再用 `ingest_posts.py` 入库。

## 收件箱格式（两种模式通用）
```
data/inbox/bench/<任意文件夹名>/
  01.jpg 02.jpg …   帖子图片，按文件名排序就是图序（截图也可以）
  caption.txt       第一行是标题，后面是正文原文（#话题 会自动提取成标签）
  metrics.txt       可选，每行一个「键: 值」：链接 / 作者 / 日期 / 点赞 / 收藏 / 评论 / 行业 / 采集方式 / 采集日期
  comments.txt      可选，每行一条「评论原文 | 意向判断理由」；只写评论内容，不写用户名、头像
```
例子见 `examples/demo/inbox/`。

## 模式 A · 手动提供（任何 agent 都能用）
用户直接给帖子：截图、图片文件、复制的正文，或者链接加截图。
```
把用户给的每篇对标帖整理成 data/inbox/bench/<简短名>/：图片按顺序命名为 01、02…；标题和正文原样写进 caption.txt；
看得到的链接、作者、日期、赞藏评写进 metrics.txt（看不到就不写，不要补 0）；用户贴了评论区截图的，把意向评论写进 comments.txt。
然后运行 python scripts/ingest_posts.py --data data。
```
你没有浏览器控制能力时，**只能用模式 A**。即使 `collection.mode` 写的是 browser，也请用户手动提供。

## 模式 B · 专用小号自动搜集（需要能控制浏览器的 agent）
**开始前逐条确认，任何一条不满足就停下，改用模式 A：**
1. `collection.mode: browser`，`is_main_account: false`，`user_accepts_platform_risk: true`。
2. 用户提供的是**专门用来研究的小号**，不是品牌的主运营账号，也不是员工的个人主号。
3. 用户知道并接受：自动浏览可能触发平台限制（限流、要求验证、封号），后果由这个小号承担。

**给有浏览器控制能力的 agent 的提示词**
```
你在用浏览器帮用户收集对标帖，只能像一个正常人那样使用小红书的普通网页。
1. 打开 https://www.xiaohongshu.com，请用户亲自登录 brand.yaml 里写明的专用小号。
   扫码、短信验证码、滑块或图形验证码都由用户本人完成，你只等待，不代为操作。
   不要读取、导出、保存 cookie、token 或密码，也不要把登录状态复制到别处。
2. 依次搜索 collection.keywords 里的关键词。每个关键词选“综合”或“最热”，从结果里挑和本品牌行业、人群相关的帖子，
   优先挑互动高、近一年发布的。广告、无关内容和明显搬运的帖子跳过。
3. 逐篇打开帖子详情页，像人一样浏览：
   - 用浏览器正常的“另存为”或截图保存每张配图，按顺序命名为 01、02… 放进 data/inbox/bench/<关键词>_<序号>/；
   - 把标题、正文原样写进 caption.txt；
   - 把页面上**看得到的**点赞、收藏、评论数、发布日期、作者名和地址栏里的帖子链接写进 metrics.txt，
     并注明「采集方式: 专用小号自动」「采集日期: <今天>」；
   - 评论区只看已经加载出来的顶层评论，有明确意向的（问价、问地点、问能不能预约或购买）摘短句写进 comments.txt，
     不记录用户名、头像和评论ID。
4. 控制节奏：每次最多打开 collection.max_posts_per_session 篇（默认 30）；两篇之间随机停 collection.pause_seconds 秒（默认 8–20 秒）；
   每打开 10 篇左右多休息一会儿。出现验证码、“操作频繁”或要求重新登录时立刻停下，告诉用户，由用户决定是否继续，不要自己绕过。
5. 浏览器“另存为”的图片一般落在系统的“下载”文件夹，要逐篇移到 data/inbox/bench/<关键词>_<序号>/ 并按 01、02… 重命名。
   收集结束后退出浏览器，运行 python scripts/ingest_posts.py --data data --config config/brand.yaml。
   这一步会核对模式 B 的三条前置确认，没确认的帖子会被拒绝入库。之后进入下面的“拆解”。
受监管行业（医疗、医美、教育、金融）：不要搜索或保存患者案例、术前术后对比、个人病情这类内容；评论里的健康信息、病情一律不摘录，只记录“问价/问地点/问预约”这类意向。
禁止：调用平台私有接口或抓包；抓取 cookie、token；破解或绕过验证码；用任何反检测、伪装指纹或多开手段；
批量下载与研究无关的内容；使用品牌主运营账号。保存下来的对标图片只能用于研究，不能拿来二次使用或商用。
```

## 拆解（两种模式相同）
**给 agent 的提示词**
```
运行 python scripts/ingest_posts.py --data data 之后，样本库里会多出 BM-*** 的空壳行（观察字段写着【待拆解】）。
打开 data/raw/bench/<样本ID>/ 里的每张原图，严格按 templates/拆解模板.md 的 A 部分填写：
1. A0 筛选门槛：判断这篇是否在 collection.bench_window_days 天内发布、是否有 ≥ collection.min_intent_users 位不同用户的意向评论。
   能核实的填“正式合格”，不能的填“候选”，并在「评论核验口径」里写清楚核验了哪些评论、怎么核的。
2. A2 逐帖摘要：图序观察、设计结论、点击机制_推断、咨询解释、本品牌迁移、不可照搬、查看边界。
3. A3 逐图详解：每张图写 构图 / 主体比例 / 字体与配色 / 信息作用 / 优点与局限 / 可迁移到<本品牌> / 推断与边界，
   分别填进 构图_观察、主体比例_目测外接框、字体层级_观察、配色_观察、文案卖点_观察、阅读顺序_推断、可取之处、局限、
   点击机制_推断、本品牌迁移建议、不可照搬、图示区域_近似归一坐标，并把已看实图改成“是”。
4. A4 咨询证据：检查 comments.txt 导入的行，补齐意向判断理由。
5. 遵守模板里的「通用写法规范」：观察和推断分开写；比例是目测的；字体只描述形态；颜色不冒充色值；没显示的数字不补 0；不写因果结论。
6. 填表用助手，不要手改宽 CSV：
   python scripts/fill_breakdown.py --data data template BM-004 > data/breakdown/BM-004.yaml   （只列出【待拆解】的字段）
   填好以后：python scripts/fill_breakdown.py --data data apply data/breakdown/BM-004.yaml       （列名不对会直接拒绝）
7. 运行 python scripts/build_tables.py --data data --config config/brand.yaml，直到状态报告里样本库的【待拆解】降到 0。
最后按 A5 的结构给用户写一份图示决策摘要（Markdown 就行）：当前证据 / 最值得借的内容 / 优先尝试的两种首图 / 目前不能得出的结论，
以及每个主题“看见什么 / 借什么 / 改什么”。
```

**产出**：`data/inbox/bench/*`（原始收集）；`data/raw/bench/<样本ID>/Pxx.*`；`爆款样本库_样本帖子.csv`、`_样本图片.csv`、`对标咨询证据.csv`（BM-*）；决策摘要。

**给用户看什么（减负）**：只给 A5 决策摘要，一页讲清“借什么、不借什么、先试哪两种首图”。逐格的拆解明细留在表里，用户不问就不展示。

**用户过目（不是关卡，不停下来等）**：拆完给用户看一页决策摘要，顺带问一句“对标帖找得对路吗？”，用户没意见就自动往下走。模式 B 下，登录和验证由用户本人完成，是否继续采集由用户决定（这属于“缺必问事实”关卡）。

**完成标准**：每篇都按模板 A 填完，没有剩下【待拆解】；正式合格和候选分开统计；决策摘要已经交给用户。
