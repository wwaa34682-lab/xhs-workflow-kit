# 第 10 步 · 投流复盘 → 回写 → 下一篇

**目标**：按 CPL 定胜负（CTR 为辅），判断各版本是放量、小额对照还是停掉。把结论写成提议，专家确认后进入风格锁，下一篇回到第 4 步时就用上。

**没有聚光时**：两版都发完 7 天后，导出笔记数据，运行 `recover_juguang.py --organic <新导出.csv>`，再运行 `ab_test.py verdict --draft D001 --write-back`。脚本会自动按收藏率判胜负，写回的规则编号是 `SL-ORG-…`。
没有真实数据想先演练：运行 `recover_juguang.py --sim --organic-proxy "A=历史帖子标题1" --organic-proxy "B=历史帖子标题2" --draft D001`，再运行 `ab_test.py verdict --draft D001 --sim`。

**模拟规则只能否决**：`SL-SIM-*` 运行 `ledger.py approve` 时脚本会拒绝生效，只能加 `--reject`。否决时，关联的评审回流会自动标成“不需要”。
还有挂着的“待回写”：`python scripts/ledger.py --data data resolve --id <回流ID> --status 不需要 --note "<原话>"`（`--id all-sim` 一次清掉全部模拟来源的）。

**真实数据的提示词**
```
跑了 3–7 天以后，请用户再导出一次聚光计划列表，然后：
python scripts/recover_juguang.py --config config/brand.yaml --data data --plan <新导出.csv> --range "<区间>"
python scripts/ab_test.py --config config/brand.yaml --data data verdict --draft D001 --write-back \
  --cover A=data/drafts/D001/out/P01.png --cover B=data/drafts/D001/out_B/P01.png
把 data/out/复盘_D001.md 和 复盘_D001.png 讲给专家：谁胜出、是否过了门槛、哪些该停。
专家同意的提议：python scripts/ledger.py --data data approve --id <SL-AD-…> --note "<原话>"
专家不同意：--reject。最后运行 build_tables.py，并把发布队列状态改成“已复盘”。
```

**还没有真实数据？用模拟走通流程**（例如刚建好工作流、想演练给同事看）
```
用历史计划“扮演”新稿件的各个版本（挑首图风格最接近的历史计划当替身），只写 data/sim/：
python scripts/recover_juguang.py --config config/brand.yaml --data data --sim --draft D001 \
  --proxy "A=<历史计划名>" --proxy "B=<历史计划名1>|<历史计划名2>" --proxy "D=<历史计划名>"
python scripts/ab_test.py --config config/brand.yaml --data data verdict --draft D001 --sim --write-back
所有产出都带【模拟演练，非真实数据】。写回的规则状态是“提议·待专家确认（模拟，未生效）”，不能当作已经验证。
模拟复盘**不会给停投、放量建议**，只写“演练里暂列第一 / 演练里偏弱 / 演练对照”。给用户讲的时候也只说“流程走通了”，不要说“该停哪个计划”。
```

**决策规则**（SL-G13，只用于真实数据）
- CTR 要展现 ≥1000 才判；CPL 要消费 ≥2×账户CPL 或留资 ≥3 才判。没过门槛的，结论写“暂定”。
- 消费 ≥1×账户CPL 仍然 0 留资：停。
- CTR 不及格并且 0 留资：停。
- CPL 最低的：放量，跑到门槛后再确认。
- 其余：小额对照。

**人工关卡**：放量、停投在聚光里由用户操作；规则生效要专家确认。

**完成标准**：复盘报告已交给专家；风格锁已更新（生效或否决）；发布队列状态为“已复盘”。然后回到第 4 步写下一篇，这一轮的规律就用在下一篇上了。
