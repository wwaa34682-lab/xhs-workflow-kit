# 第 09 步 · 投流 A/B 测试方案【人工建计划】

**目标**：用小预算同时测 2–4 个版本（一次只改一个变量，通常是首图），按第 8 步的目标线定门槛、预算和止损线。

**给 agent 的提示词**
```
1. 和用户确定要测的版本。建议：主版 + 一个配色或版式变体 + 一版“真人出镜”首图（SL-G15）。
   真人出镜要先按 face_policy 确认可以用谁的脸。
2. 运行
   python scripts/ab_test.py --config config/brand.yaml --data data plan --draft D001 \
     --variant "A=主版" --variant "B=<变体>" --variant "D=真人出镜" --budget <用户给的预算>
3. 把 data/out/投流方案_D001.md 讲给用户，重点讲三件事：
   - 计划名必须以 D001-A / D001-B … 开头，数据回收靠这个自动关联（把要用的计划名原样发给用户，让他直接复制，不用解释编号规则）；
   - 预算不够判定门槛时，结论只能是“暂定”；
   - 止损线是多少。
```

## 没有聚光时这样做（自然流量 A/B）
```
python scripts/ab_test.py --config config/brand.yaml --data data plan --draft D001 --variant "A=主版" --variant "B=<只改一个变量>"
```
基线口径是 organic 时，脚本会自动出“轮流发两版”的方案：
- 同一账号、同一个星期几、同一时段，间隔 3–7 天，只换一个变量；
- 每版观看要过门槛，按收藏率判胜负。
- ⚠ **不要把同一篇原样发两次**（会被判重复内容、限流）。两版测同一个变量，但标题、正文开头和内页换成同主题下的不同角度，结论按“暂定”看。店主问“会不会被判重复”时就这样答；要严格对照只能用聚光。

每发一版，就用 `ledger.py --data data --config config/brand.yaml queue --draft D001 --variant A --status 已发布 --note-id <笔记ID>` 登记。导入自然流量时，脚本会按笔记ID 自动关联到 D001-A / D001-B。各版本沿用这篇稿件的专家评审结论（评审按稿件过，不用每版再审一次；但改了事实或文案的版本要重新走第 6 步）。

**怎么选变量**：每个出图预设的 `variants.B` 都只改一个变量，可以直接拿来用：
- 极简大标题：换成品牌主色底；
- 产品主体：换背景色系；
- 照片满版：换首图照片；
- 探索地图：换背景色系。

**产出**：`out/投流方案_D001.md`；发布队列里新增一行 `PQ-AB-D001`（投流方案·待人工建计划）。

**人工关卡**：在聚光建计划、设预算、上线，全部由用户操作。agent 不碰账户和钱。

**受监管行业**：改成「投流中」前要有合规审核人的「合规」通过记录；面向未成年人时还要一条 `ledger.py review --draft D001 --type 合规·投流 --verdict 通过 --reviewer <审核人> --quote "原话"`（审核人确认投流定向和话术）。

**完成标准**：用户确认方案，并回复“计划已建”。之后对每个版本运行一次 `python scripts/ledger.py --data data --config config/brand.yaml queue --draft D001 --variant A --status 投流中`（B、D 同理；版本精确匹配，不会命中方案行 PQ-AB-D001）。
