# 第 08 步 · 数据回收（有聚光看投流，没有聚光看自然流量）→ 基线和目标线

**目标**：把投流数据关联到具体帖子，算出“账户平均水平”（及格线）和“前 25% 水平”（优秀线），作为下一篇和 A/B 测试要超过的目标。

**说明**：很多专业号、企业号的自然流量几乎为 0（每篇只有几到十几次浏览），这时只看聚光数据。自然流量多的账号可以加 `--organic`。

**输入**：用户从聚光导出的 CSV。
- 计划列表：必须有，列名用聚光原样，比如 计划名称、消费、展现量、点击量、私信留资数……
- 留资列以用户确认的 `juguang.lead_field` 为准（私信留资数、表单提交数、表单预约数……都认）。导出里找不到这一列时脚本会打印 ⚠，这时先和用户核对，不要下“0 留资”的结论。
- 创意数据：可选。
- 创作者中心的笔记数据：可选。
- 时间范围：尽量长，建议 3–6 个月。

**给 agent 的提示词**
```
运行
python scripts/recover_juguang.py --config config/brand.yaml --data data \
  --plan <计划列表.csv> [--creative <创意数据.csv>] [--organic <笔记数据.csv>] --range "<开始> ~ <结束>"
然后读 data/out/数据回收_结论.md 和 数据回收_总结.png，告诉用户：
1. 基线数字：CTR、CPL、0 留资计划浪费了多少钱。
2. 目标线：及格和优秀两档，以及判定门槛。
3. 关联率：还有多少计划没关联到帖子。请用户去聚光后台查这些计划绑定的笔记ID，或告诉你哪些计划要排除。
   排除的计划：python scripts/recover_juguang.py --config config/brand.yaml --data data --exclude "<计划名>" --why "<用户原话>"（可多个 --exclude），会自动重算。
   想让基线不含正在评估的稿件：加 --baseline-exclude D001。
4. 成绩单里 CPL 最好和最差的帖子，各自的首图和标题有什么特点（对照第 2 步的拆解）。
   规律只写成“提议”，比如：
   python scripts/ledger.py --data data rule --id SL-P01 --dim 投流 --rule "..." --status 提议·待专家确认
   样本量小时要明确说“方向性”。
```

## 没有聚光时这样做
请用户在创作者中心导出笔记数据，包括曝光、观看、点赞、收藏、评论。有私信或到店咨询的，可以加一列「咨询数」手填。然后运行：
```
python scripts/recover_juguang.py --config config/brand.yaml --data data --organic <笔记数据.csv> --range "<区间>"
```
脚本会算出自然流量口径（organic）的基线和目标线：
- **收藏率**（收藏 ÷ 观看）：看了的人里有多少想留着，这是主判定；
- **互动率**：辅助判定；
- 每篇观看要达到门槛 `organic.min_views_for_judge`，默认 300。

结果写进 `数据回收_基线.json`、`_结论.md`、`_总结.png`、`_帖子成绩单.csv`，第 9、10 步直接接着用。

## 未关联的计划（减负）
不要把整张映射表丢给用户。把没关联上的计划挑出 3–5 条列给他，每条给三个选项：
「1. 是哪篇（发链接或标题）2. 排除 3. 不知道」。
选“不知道”的保持“待补”，不挡流程，也不计入任何帖子的成绩。

**产出**：`tables/投放效果库.csv`、`投放映射.csv`、`自然流量库.csv`；`out/数据回收_基线.json`、`_结论.md`、`_总结.png`、`_帖子成绩单.csv`、`_导入历史.csv`。

**人工关卡**：用户导出 CSV，补充笔记ID，决定排除哪些计划。提议的规则要专家确认后才生效。

**完成标准**：目标线已算出；没关联的计划在消费里的占比已经告诉用户；提议已交给专家。
