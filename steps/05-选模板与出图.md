# 第 05 步 · 参考图 → 针对性改编出图

**目标**：照着用户给的参考图，用本品牌的颜色、字体、主体、门店、事实，以及用户自己的照片和文案，做出首图和内页。
案例里，从零设计的第一版被专家评为“很 low”；改成“照着参考图改”后，一次就通过了。

## 硬规则：只给两个选项，没有第三个
每篇稿件出图前，必须原样问用户这一题（按 `docs/交互规范.md`，只问这一题）：
```
【第5/10步·出图】出图前选一下方式：
1.【推荐·默认】给参考图，做针对性修改：发我 1 张以上你觉得好看的图（同行帖子、海报、截图都行），我照着它的版式、字体、调色来改成你的品牌
2. 没有参考图（极度不推荐）
回复数字即可，直接回车用推荐。
```
- 版式要用户照片时（照片满版 = 作品/门店实拍，产品主体 = 产品图），在这条消息末尾顺便要 1 张，不另开一轮。照片**按稿件存**：放进 `data/drafts/<稿件ID>/`，在 `pages.yaml` 写 `cover_photo: cover.jpg`（产品图写 `cover_subject:`；A/B 换照片写 `variants: {B: {cover_photo: cover_B.jpg}}`）。不要改全局 `layout.yaml` 的照片路径，否则做第二篇会串图。
- 第二篇起（`xhs.py new --reuse-refs`）：选 1 时默认沿用上一篇的参考图（推荐），也可以发新图。这仍是“给参考图”这一个选项，选项还是只有两个。
- 用户选 2，必须再确认一次：
  `⚠ 没有参考图做出来的图片审美会非常差，之前的经验是专家直接评“很 low”。确定不给参考图吗？1. 我去找一张参考图（推荐）2. 确定，不要参考图`
  只有用户第二次也明确选“确定”，才能用通用版式出图，并在命令里加 `--no-reference-confirmed`。
- 不准替用户选 2，不准默认走 2，不准自己从网上找图当参考图。
- `render_post.py` 会强制执行这条规则：没登记参考图（`data/refs/<稿件ID>/` 至少 1 张图，加上 `layout.yaml` 里填完的 `reference` 拆解），也没有 `--no-reference-confirmed`，就拒绝出图。用了这个参数会自动记进评审回流库，第 6 步评审时要再请用户补一次参考图。

## 选项 1 的流程（给 agent 的提示词）
```
1. 把用户给的参考图存成 data/refs/<稿件ID>/ref_01.jpg、ref_02.jpg…（只作参考，不进成品，不商用原图）。
2. 按 templates/参考图拆解清单.md 逐项看图，写进 config/layout.yaml 的 reference：
   breakdown 的 版式 / 字体 / 调色 / 主体 / 装饰 / 文字位置，再写 kept（保留了什么）和 changed（改了什么）。
   第一次用时，从 config/layouts/ 里挑和参考图最接近的预设（极简大标题 / 产品主体 / 照片满版 / 探索地图，见 config/layouts/README.md），复制成 config/layout.yaml。
   不要默认用探索地图（圆形巨物 + 路线），除非参考图本身就是这种风格。
3. 把拆解落实到参数：canvas、palette、cover.background、cover.subject、doodles、route、slots 的位置和字号、inner.frame / photo_box。
   - 主体：sphere（球、果实、气泡这类圆形巨物；pattern: dimples 是颗粒质感）、disc（扁平圆）、
     image（产品抠图 PNG，比如一碗面、一瓶精华），或者 none。
   - 有多家门店就开启 route，节点会自动取 brand.yaml 的 locations。只有 1 家店时自动画定位针，不会出现孤立的“01”节点。
     渲染时如果提示“路线压在主体上”或“和文字槽重叠”，就调 route.y 或槽位的 y。
   - 价格不放大：风格锁 SL-G14 生效时，脚本会把首图价格的强调字号压到正文的 1.15 倍以内。
   - 压在主体上的文字一律用 on_subject 样式，即描边加投影（SL-G07）。不要加硬底卡片。
   - 风格锁里已经生效的规则优先于参考图。
4. 写 data/drafts/<稿件ID>/pages.yaml：cover 下写各槽位的文字，inner 下写 3–5 页内页（title、photo 或 photos、caption）。
   照片只用用户自己的、有授权的实拍。事实用 {offer.0.price_text} 这类写法从 brand.yaml 引用，不要手打数字；强调的部分用 **…** 包起来。
5. 渲染：python scripts/render_post.py --config config/brand.yaml --layout config/layout.yaml --draft data/drafts/<稿件ID>
   要出 A/B 套系，在 layout.yaml 的 variants 里写差异，加 --variant B。
6. 自己先检查 out/preview.png：
   - 有没有【待业务确认】、文字溢出或压脸；
   - 缩成手机信息流大小（约 360px 宽）时，主标题还能不能看清；
   - 有没有违反风格锁；
   - 和参考图放在一起比，气质像不像。
   发现问题就改参数重出。
7. 人脸按 brand.yaml 的 face_policy 处理，需要时运行 scripts/face_swap.py（blur / sticker / swap）。
   swap 模式要加 --data data --draft <稿件ID>，会自动把发布队列标成“含AI内容=是”。
   处理完在 pages.yaml 写 faces: "<结果>"（如“无人脸”“P03 顾客已打码”“店主本人，已授权”）。
8. 给用户看「参考图 | 成品」对比（render_post.py 自动生成 out/参考对比.png），写 3 条以内“保留了”、3 条以内“改成了”，问“哪里还要改”。
   用户的原话写进 pages.yaml 的 reference_feedback；每提一条具体意见，就追加到 reference.iterations，只改他说的地方，重出再给他看。满意后进入第 6 步。
   inner.styles 可以单独给内页定样式（覆盖顶层 styles 的同名样式），例如内页用深色实字、首图用白字描边。
```

## 选项 2 的流程（用户二次确认之后）
```
按行业用 config/layouts/ 的推荐预设（reference 保持未填写），照常写 pages.yaml，然后运行
python scripts/render_post.py ... --no-reference-confirmed
交付时附一句：“这是没有参考图的通用版，审美会差一些。评审前如果能找到一张参考图，我可以马上按参考图重做。”
```

**产出**：`data/refs/<稿件ID>/` 参考图；`layout.yaml` 的 reference 拆解；`data/drafts/<稿件ID>/out/P01.png…Pnn.png`、`preview.png`；有套系的话还有 `out_B/`。

**人工关卡**：用户提供参考图和照片，决定人脸怎么处理；选“没有参考图”必须二次确认。

**完成标准**（`xhs.py status` 按这几条判断，快速起步只出首图不算完成）：
- 首图 + 3–5 张内页都出了，照片都找得到（缺照片会列出来）；
- pages.yaml 写了 faces（人脸已按规则处理）和 reference_feedback（用户看过参考对比）。
- 参考图已登记、拆解已填完；如果选了选项 2，已二次确认并记录。
- 图上没有【待业务确认】。
- 只用三款字体；主体上的文字清晰可读；含 AI 的已经标注。
- 已经给用户看过对比，并说明了保留和改动。

> 文字太长时（例如品牌名很长）脚本会把那一行整体等比缩小到画面内，并在提示里说明缩到多少；缩得太多（<75%）就该改短标题，而不是接受小字。
