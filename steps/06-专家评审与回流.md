# 第 06 步 · 专家评审 → 回流【人工关卡】

**目标**：专家（`brand.yaml` 里的 `reviewer`）对图和文案下结论。每一条意见都记进评审回流库，能沉淀成规则的写进风格锁，让下一篇不再犯同样的错。

**给 agent 的提示词**
```
把 data/drafts/D001/out/preview.png 和 copy.md 发给专家，请专家给出结论：通过 / 不通过 / 修改后再审。
如果“不通过”但专家说不清原因，给出多选项帮他定位，比如：照片质感差、排版像 PPT、像促销或促销海报、文案太直白、不像小红书。
对每一条意见：
1. 原话照抄，记一条评审：
   python scripts/ledger.py --data data --config config/brand.yaml review --draft D001 --round 1 --verdict 不通过 --where P01 --type 排版 \
     --quote "<原话>" --suggest "<你的改法>" --target <要改的规则ID> --reviewer "<专家名>"
2. 能抽象成规则的（“以后都要/都不要…”），新增或修改风格锁，并用 --from 关联评审行：
   python scripts/ledger.py --data data rule --id SL-B0x --dim ... --rule ... --must ... --ban ... --from RV-D001-01 --status 生效·专家确认
   只针对这一篇的意见（比如“这张换个角度”）不写进规则。
3. 按新规则回到第 4 或第 5 步重出，再提交评审，轮次 +1。
4. 专家说“通过”以后，记录 --verdict 通过。发布队列会自动变成“已通过，待发布”。
```

**产出**：`评审回流库.csv`；更新后的 `风格锁.csv`；发布队列的状态。

**人工关卡**：结论只能来自专家本人，agent 不能代判。专家对颜色、字体给出偏好时，至少出 2–4 版对比图让他挑。

**完成标准**：最后一轮的结论是“通过”；所有“否”的回流都已回写，或者写明“不需要”（状态报告里待回写为 0）。

> **补参考图提醒**：如果评审回流库里这篇有一条「问题类型=缺参考图」（第 5 步用了 `--no-reference-confirmed`），评审时先再问用户一次：“这版是没有参考图的通用版。现在给我一张参考图，我按它重做，通常会好很多。1. 给参考图重做（推荐）2. 就用这版送审”。
