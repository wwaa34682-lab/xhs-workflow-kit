# 拆解模板（沿用原案例用户自己的两套报告结构）

> 来源：一个线下门店品牌实战里，用户自己交付的两类拆解报告：
> ① **对标库交付包**：可编辑 Excel，三个工作表（样本总览 / 逐图设计 / 咨询证据），两份 CSV，7 页图示决策摘要，逐图详版 PDF；
> ② **自有账号视觉复盘**：每个账号一份 PDF，分「摘要 / 逐帖小结 / 逐图详解」三种页面。
> 下面的章节标题、字段名和顺序都**原样保留**，只改了两类内容：行业专属措辞（例如「课程意向评论」改成「意向评论」，「可迁移到 原品牌名」改成「可迁移到 <本品牌>」）和举例。
> 每个字段对应哪一列，见「→ 列名」。填写示例在 `templates/拆解模板_填写示例.md`，用的是虚构的 demo 帖子。

## 通用写法规范（两套报告都用）
- **观察与推断分开记录。** 看得到的写进“观察”字段；点击机制、阅读动线只能写进“推断”字段，并注明“是推断，不是因果结论”。
- 构图比例、主体比例、区域坐标是**目测近似外接框**，不是像素分割或眼动测量。
- 字体只描述形态，**不确认具体字库**。颜色描述来自实图，**不冒充品牌色值测量**。
- 互动数字照抄原样。**没有显示数字就不补零**。没有曝光、私信、到店、成交数据时，不做转化或设计上的因果推断。页面显示的是“编辑于”时，写明“首次发布日期未知”。
- 有咨询，不等于图片转化高；评论和设计同时出现，不等于设计带来了咨询，更不等于成交。
- LIVE 图和视频只分析静态配图，并注明这一点。
- 对标原图只用于设计研究，**不当作本品牌可用的商业素材**。图上的他牌价格、承诺、资质只记录“展示了什么”，不核验，也不背书。
- 页脚固定写：`观察与推断分开记录；原帖图片仅作设计研究参考，不作为<本品牌>可用商业素材。`

## A. 对标帖拆解（对标库交付包结构）

### A0 筛选门槛（写在「样本总览」表头说明里）
- 目标窗口：观察日往前 **1 年**内发布（可在 `brand.yaml collection.bench_window_days` 改）。
- 每篇都要核验，至少 **11 位不同的真实咨询用户**（可在 `collection.min_intent_users` 改）。达不到的标“候选”，**不计入正式样本数**。
- 门槛按行业调：咖啡、餐饮、零售这类评论多是“求地址/怎么去/多少钱”，这些都算意向；评论本来就少的行业，可以把 `collection.min_intent_users` 调到 3–5，并在「评论核验口径」里写明。受监管行业（医疗等）只记录评论里的意向，不摘录健康信息。
- 「日期原样」和「日期证据状态」分两列写；空值表示原始记录没提供，**不要补推**。
- 咨询数字都是“已核下限”。评论核验口径要写明，比如：“只加载了 N 条顶层评论，没看全部评论；作者回复已排除；按网页用户标识核过 N 人都不相同；不保存用户名和头像。”

### A5 图示决策摘要（交付包里的 7 页 PDF，第 1 步结束时交给用户）
1. **封面页「先借信息组织，再决定视觉样式」**，五个小节：当前证据 / 最值得借的内容 / 优先尝试的两种首图 / 目前不能得出的结论 / 怎样使用这套文件。
2. **正式样本页**：每篇写三行，“看见什么 / 借什么 / 改什么”，再写一句“对<本品牌>最有用的组合”。
3. **主题页 01–04**，每页挑 2 篇样本，同样写“看见什么 / 借什么 / 改什么”，页尾写一句“可测试方向 / 价格处理 / 推荐角色分配 / 不能照搬”。原四个主题是：01 服务识别：先让人知道这是什么；02 条件与费用：重要限制也要容易看见；03 风格与排期：好看之外，要帮助做决定；04 信任证据：人物、证书与结果要分清。（结构保留原样；主题名可按行业微调，比如产品型门店把 03 写成“风格与规格/时段”，没有人物和证书的行业把 04 写成“口碑与实拍证据”。受监管行业的 04 必须写清哪些资质已核实。）
4. **05 把研究变成一组可制作的图片**：依次写 首图 / 第2图 / 第3图 / 第4图 / 第5图 / 画面统一 / 验证再升级。
页脚：`<观察日期>观察快照。原帖图片仅供设计研究，<本品牌>公开制作需使用自身真实资产。`

## C. 两套模板在数据回收、风格锁里怎么用
- 第 3 步（风格锁）主要取：对标的「本品牌迁移 / 不可照搬」，自有的「需要调整 / 具体改法」，账号摘要的「优先动作」。
- 第 8 步（数据回收）靠 `标题`、`笔记ID` 关联投流计划，成绩单会把首图的图片角色和观察描述带进来。
- `ingest_posts.py` 只建空壳行：能自动填的元数据先填上（尺寸、SHA256、链接、正文、互动原样），其余观察字段先写 `【待拆解】`，再由 agent 按本模板逐项填写。
